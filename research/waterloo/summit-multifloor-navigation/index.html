Summit XL Multi-Floor
Autonomous Navigation

System-level integration for multi-floor mobile-robot navigation using Summit XLS, ROS navigation, vision-based pose estimation, WAM manipulation, elevator interaction, and floor-specific maps.

Project Overview

Multi-floor navigation as an integrated robotics task

The system was developed around a practical scenario: navigate from a laboratory on the third floor to the elevator, interact with the elevator controls, transition between floors, and continue navigation toward the first-floor Robohub.

Summit XLS Mobile robot platform
ROS Navigation & task integration
ZED + ArUco Vision-based pose estimation
WAM 7-DOF Elevator interaction

Mapping & Navigation

Floor-specific maps and autonomous navigation

Navigation maps were created for both the first and third floors. The Summit XLS was configured and tested to localize and navigate within each mapped environment.

Physical navigation tests were carried out from the laboratory area to the elevator lobby, establishing the mobile-navigation portion of the multi-floor workflow.

System Architecture

Navigation, perception, manipulation, and task control

The system connected the Summit XLS navigation stack, WAM manipulator, ZED camera, task-control software, inverse kinematics, and networked computers.

MOBILE NAVIGATION

Summit XLS

ROS navigation and move_base were used for localization, goal execution, and autonomous movement within the mapped floors.

PERCEPTION

ZED + ArUco

Vision-based marker detection was used to estimate the pose required for elevator-button interaction.

MANIPULATION

WAM 7-DOF

The WAM manipulator was integrated with inverse kinematics and pose calibration for elevator-button interaction.

TASK CONTROL

ROS task orchestration

A core task-control node coordinated navigation, perception, manipulation, and elevator-interaction stages across the system.

Elevator Interaction

Vision-guided manipulation for button pressing

Elevator interaction required the perception and manipulation subsystems to share a consistent spatial reference. ArUco markers were used as visual landmarks for estimating the target pose.

The WAM manipulator then used the estimated pose and inverse-kinematics solution to approach and press the elevator control.

Interaction pipeline

  • Detect ArUco marker
  • Estimate target pose
  • Transform pose into robot/manipulator frame
  • Solve WAM inverse kinematics
  • Execute button-press motion
Calibration & Debugging

Coordinate-frame alignment

Pose-estimation reliability depended on consistent camera, robot, and manipulator coordinate frames.

Frame-alignment issue

Testing indicated that the camera frame and the other system frames were not consistently aligned, introducing pose offsets during manipulation.

Calibration approach

Base ArUco markers were added to the Summit platform to establish a visual reference, and larger markers were used to improve pose-estimation reliability.

System Integration

Practical robotics troubleshooting

Integrating multiple robotic subsystems required debugging beyond navigation and manipulation algorithms.

Communication, networking, planner behavior, and hardware recovery all affected whether the integrated demo could operate reliably.

Issues addressed

  • CAN communication failure
  • Summit control loss
  • Remote-PC network disconnection
  • Router and network reconfiguration
  • Local-planner oscillation near the goal
  • Pose-estimation and frame-alignment errors

Project Scope

System integration through elevator interaction

The work established the navigation maps, Summit XLS navigation setup, elevator approach, perception, manipulation, and task-integration components required for the larger multi-floor scenario.

The project concluded before a fully autonomous end-to-end execution from the third-floor laboratory through the elevator to the first-floor Robohub was completed.
