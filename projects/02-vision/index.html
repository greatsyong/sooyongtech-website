1. Project Objective

The goal of this project was to build a real-time robotics perception pipeline in ROS 2 that integrates object detection, persistent multi-object tracking, instance segmentation, runtime visualization, and quantitative performance logging.

The project focuses on system integration rather than custom model training. Pretrained YOLO weights were used so that the engineering effort could concentrate on ROS 2 data flow, GPU inference, tracking continuity, annotated image publication, latency measurement, and reproducible evaluation.

2. System Architecture

The perception stack is organized as a modular ROS 2 pipeline. A camera publisher acquires frames from the local webcam and publishes them as sensor_msgs/Image messages. The final unified perception node subscribes to the image stream, executes YOLO-based tracking and instance segmentation on the GPU, overlays runtime diagnostics, and republishes the annotated result.

3. Technical Implementation

3.1 Camera Interface

OpenCV acquires webcam frames through cv2.VideoCapture. Each frame is converted to a ROS 2 image message using cv_bridge and published at approximately 30 Hz.

3.2 Object Detection and Tracking

The perception system uses the Ultralytics YOLO interface with pretrained weights. Persistent tracking allows object IDs to remain associated with detections across consecutive frames, providing temporal continuity beyond independent frame-by-frame detection.

3.3 Instance Segmentation

The final system uses a YOLO segmentation-capable model to generate an independent pixel-level mask for each detected object. This is instance segmentation rather than semantic segmentation: multiple objects from the same class remain individually identifiable.

3.4 Unified Perception Node

The final node combines tracking and instance segmentation in a single inference path to avoid redundant model execution. It overlays FPS, object count, processing latency, device information, bounding boxes, class confidence, persistent IDs, and instance masks before publishing the annotated image.

Design choice: one segmentation-capable YOLO model provides both object localization and masks, while tracking state is maintained across frames. This avoids running independent detection and segmentation models concurrently.

4. Experimental Setup

Hardware

  • NVIDIA GeForce RTX 5060 Laptop GPU
  • Integrated webcam input

Software

  • Ubuntu 22.04
  • ROS 2 Humble
  • Python 3.10
  • PyTorch 2.11.0 + CUDA 12.8
  • Ultralytics 8.4.147
  • OpenCV 4.10.0
  • NumPy 1.26.4

The camera publisher was configured at approximately 30 Hz. Runtime data were logged to CSV for every processed frame, including timestamp, observed FPS, total processing latency, YOLO inference latency, and detected-object count. The first frame was excluded from steady-state statistics because it contained initialization and GPU warm-up overhead.

Demo screenshots and video are qualitative visualization only. The quantitative results reported below come from the separate 2,136-frame benchmark run.

Interpretation of FPS: observed FPS should not be treated as unconstrained model throughput. The input publisher was configured near 30 Hz, and ROS 2 callback scheduling introduces short-term timing jitter. Processing and inference latency are therefore more meaningful indicators of runtime performance.

5.2 Processing and Inference Latency

Mean processing latency was 18.26 ms and P95 processing latency was 24.87 ms. A nominal 30 Hz camera stream has a frame period of approximately 33.3 ms, so the measured P95 processing latency remained below the nominal camera frame interval.

5.3 Processing Latency Distribution

The latency distribution contains two visible operating bands rather than a perfectly unimodal distribution. Possible contributors include variations in tracking updates, mask rendering, object count, ROS 2 callback scheduling, and visualization overhead. The available measurements do not isolate a single cause, so the bimodal-like pattern is reported without attributing it to one subsystem.

8. Engineering Discussion

What This Project Demonstrates

  • ROS 2 node and topic integration for deep-learning perception.
  • GPU-accelerated real-time inference.
  • Persistent multi-object tracking.
  • Instance-level segmentation.
  • Runtime instrumentation and quantitative benchmarking.
  • Launch/package structure for reproducible execution.

Limitations

  • The model uses pretrained general-purpose weights rather than a robotics-specific custom dataset.
  • The experiment uses a local webcam rather than a calibrated robot camera or multi-camera system.
  • Observed FPS is constrained by the publisher rate and is not maximum model throughput.
  • The current benchmark does not independently profile preprocessing, tracking, rendering, ROS 2 transport, and postprocessing overhead.
  • Tracking accuracy metrics such as MOTA, HOTA, or IDF1 were not evaluated because labeled tracking ground truth was not used.

Future Work

  • Integrate calibrated RGB-D or stereo input.
  • Publish structured detection and tracking messages in addition to visualization images.
  • Benchmark CPU and GPU execution separately.
  • Profile individual pipeline stages.
  • Evaluate tracking accuracy on a labeled benchmark.
  • Fine-tune the model for robotics-specific perception if required.
  • Fuse visual detections with LiDAR or depth sensing in a later sensor-fusion project.

9. Key Takeaway

2,136-frame benchmark: the ROS 2 perception pipeline maintained stable real-time operation with 18.26 ms average processing latency, 24.87 ms P95 processing latency, and 8.70 ms average YOLO inference latency while processing scenes containing up to 11 detected objects.
